# Capri — план основного функционала (notch + приложение)

Дата: 2026-10-29. Заменяет фазы P0–P6 из `MVP_SPEC.md` для первой рабочей версии.
Цель одна: **видеть все сессии Claude Code и Codex на всех машинах, мгновенно узнавать,
когда сессия ждёт меня, и отвечать ей из выреза экрана (notch)**. Вход — через аккаунт Codex.

## 0. Что оставляем и что выкидываем

Оставляем из прототипа: нативное приложение Swift/AppKit, `OverlayGeometry`, стиль окна
сессий (`DashboardView`), правила приоритетов статусов из `packages/core/session-state.ts`.

Откладываем: бродящего персонажа (остаётся опцией, по умолчанию выключен), Telegram,
голос, Markdown-память, удалённый релей, Node-демон и пустые `packages/*`.

**Архитектура — только Swift, один процесс.** Отдельный TypeScript-демон и IPC для
одного пользователя не нужны. Reducer статусов портируем в Swift вместе с тестами.

## 1. Как это выглядит

### Notch (главное)
- **Свёрнутый вид**: чёрное «продолжение» выреза, по бокам от него:
  слева — иконка/мордочка Capri, справа — счётчики: 🟠 N «ждут меня», ⚪︎ N «работают».
  Нет активности — notch выглядит как обычный вырез.
- **Новое «ждёт меня»**: notch на 2–3 с раскрывается вниз с названием проекта и
  первой строкой вопроса + короткий звук (выключаемый).
- **Наведение** раскрывает панель ~440×320: список сессий, которые ждут, сверху самые
  старые. На строке: проект · хост · агент · сколько ждёт · текст вопроса/запроса
  разрешения. Действия: поле быстрого ответа, кнопки вариантов для диалогов разрешений
  (`1 Yes` / `2 Yes, don't ask` / `3 No`), «Открыть» (терминал с `tmux attach`),
  «Подробнее» (основное окно).
- Экран без выреза / внешний монитор: такая же «пилюля» по центру под строкой меню.
- Полноэкранные приложения: свёрнутый вид скрыт, всплывает только при новом «ждёт меня»
  (настройка).

### Основное окно (клик по Capri / пункт меню)
Переделанный `DashboardView` на реальных данных:
- Слева хосты: Этот Mac, timoserver, quiz (из `~/.ssh/config`), статус соединения.
- Список сессий с фильтрами «Ждут меня / Работают / Все».
- Справа выбранная сессия: последние ~60 строк экрана (`capture-pane`), краткая сводка
  от Codex, история событий, поле ответа.

### Строка меню
Значок со счётчиком «ждут меня», пункты: Открыть Capri, Пауза уведомлений на 1 час,
Настройки, Выход.

## 2. Как детектить сессии и «нужен инпут»

### Источники правды (по убыванию точности)
1. **Хуки Claude Code** — точные события.
   - `SessionStart` → сессия появилась; `UserPromptSubmit` → работает;
   - `Notification` → **ждёт меня** (тип в поле `notification_type`: запрос разрешения,
     простой без ответа и т.п. — проверить точные значения в спайке);
   - `Stop` → закончил ход, ждёт следующей задачи; `SessionEnd` → закрыта.
   - Payload даёт `session_id`, `cwd`, `transcript_path`, `message`.
2. **Хуки Codex** (`~/.codex/hooks.json`, Codex 0.147 их поддерживает) и `notify`
   (событие конца хода). Точный список событий взять из
   `codex app-server generate-json-schema` / документации в спайке.
3. **Разбор экрана tmux** (как `orc state` в archestor) — для сессий, запущенных до
   установки хуков, и для диалогов, которые хук не покрывает:
   `esc to interrupt` → работает; пустая строка `❯` → ждёт; диалог
   `Do you want to …` / нумерованные варианты → ждёт разрешения. Помечать
   `confidence: inferred`.

### Хук-скрипт `capri-hook`
Маленький python3-скрипт (python есть на всех трёх машинах), ставится в `~/.capri/bin/`:
читает JSON из stdin, добавляет `ts`, `host`, `agent`, `$TMUX_PANE` и имя tmux-сессии
(`tmux display -p -t $TMUX_PANE '#S'`), дописывает одну строку в `~/.capri/events.jsonl`.
Ничего не блокирует, выходит с 0 за <50 мс, никогда не ломает сессию.

Установщик (из приложения, по хостам):
- **сливает** хуки в `~/.claude/settings.json`, не затирая существующие
  (на timoserver уже есть PreToolUse/PostToolUse/SessionStart/PostToolUseFailure),
  делает бэкап, умеет удалять только свои записи;
- для Codex: добавляет в `hooks.json`; `notify` уже занят Codex Computer Use —
  ставить обёртку, которая вызывает и оригинальную программу;
- ротация `events.jsonl` (например, >5 МБ → `.1`).

### Сбор событий
- Mac: `DispatchSource` на `~/.capri/events.jsonl`.
- Удалённые хосты: на каждый хост одно постоянное соединение
  `ssh -o BatchMode=yes -o ServerAliveInterval=15 <host> 'tail -n 0 -F ~/.capri/events.jsonl'`
  плюс при (пере)подключении снимок: последние события на сессию + `tmux list-panes -a`.
  Переподключение с backoff; после сна/пробуждения — переподключить и снять снимок.
- Хосты из `~/.ssh/config` Мака: `timoserver`, `quiz`. Список включаемых хостов — в настройках.
- Поллинг экрана — только для сессий без хуков и только раз в 5–10 с, ограничение
  объёма вывода.

### Модель сессии и статусы
Ключ: `host + agent + session_id`; tmux-цель (`%pane` + имя сессии) — отдельное поле.
Сессия без tmux (Terminal.app, приложение Codex) — только «наблюдение», ответ недоступен.

Статусы: `running`, `needs_input` (вопрос/разрешение), `idle` (закончил, ждёт задачу),
`error`, `rate_limited`, `disconnected`, `unknown`.
Приоритет как в прототипе: `needs_input` > `rate_limited`/`error` > `idle` > `running`.
`disconnected` хоста не стирает известный статус сессии. Дедуп уведомлений: одно
уведомление на переход в `needs_input`.

«Ждут меня» в notch = `needs_input` + опционально `idle` дольше N минут (настройка).

## 3. Ответ в сессию

- Только для сессий в tmux. Текст — через `tmux load-buffer -` + `paste-buffer -p`,
  затем отдельный `Enter` (проверено в `orc`: кириллица, кавычки, `$` проходят).
- Диалоги разрешений — отправка одной клавиши варианта, не текста.
- Перед отправкой: статус не `running`, в поле ввода нет чужого набранного текста
  (иначе отказ с объяснением), один писатель на сессию.
- После отправки ждать событие `UserPromptSubmit`/смену экрана; не пришло за 5 с —
  показать «не доставлено».
- Каждая отправка пишется в журнал.

## 4. Вход через Codex

- Capri запускает `codex app-server` (stdio JSON-RPC) с тем же `CODEX_HOME`, что и CLI.
- При старте — запрос аккаунта; не залогинен → экран «Войти через ChatGPT» →
  `account/login/start` → браузер. Уже залогинен в CLI → вход мгновенный.
- Сырой `auth.json` не читать и не копировать.
- Что Codex делает в Capri:
  - однострочная сводка «что спрашивает сессия» для notch (по последним строкам экрана /
    сообщению хука, с вырезанием секретов);
  - чат «что сейчас ждёт меня?» по всем сессиям;
  - черновики ответа (вставляются в поле, отправляет только пользователь);
  - показ лимитов аккаунта (`account/rateLimits/*`).
- Точные имена методов — сгенерировать схему: `codex app-server generate-ts`.

## 5. Этапы

**Этап 0 — спайки (1 день)**
1. Notch-панель: геометрия выреза через `NSScreen.auxiliaryTopLeftArea/RightArea`,
   панель над строкой меню, клики мимо проходят насквозь, внешний монитор.
2. Записать реальные payload хуков Claude (`Notification`, `Stop`, `UserPromptSubmit`)
   на Маке и на timoserver; события Codex hooks/notify.
3. `codex app-server`: инициализация, чтение аккаунта, вход, один короткий ход.
Выход: все три работают, неизвестные записаны в `docs/VALIDATION.md`.

**Этап 1 — конвейер событий**
`capri-hook` + установщик (слияние, бэкап, удаление) + сбор локально и по ssh +
reducer статусов в Swift с тестами на записанных payload.
Готово, когда: запрос разрешения в Claude на `quiz` появляется в состоянии Capri ≤3 с.

**Этап 2 — notch**
Свёрнутый вид, всплытие на новое «ждёт меня», раскрытие по наведению, быстрый ответ,
кнопки разрешений, «Открыть» в терминале.
Готово, когда: можно ответить сессии на `timoserver`, не открывая терминал.

**Этап 3 — основное окно**
`DemoStore` → `SessionStore` на реальных данных, просмотр экрана, ответ, фильтры, хосты.

**Этап 4 — Codex**
Вход, сводки в notch, чат «что ждёт меня», лимиты.

**Этап 5 — стабильность**
Автозапуск, сон/пробуждение, обрыв сети, single-instance, уведомления macOS,
пауза на час, замер энергопотребления.

## 6. Критерии готовности MVP

- Все Claude-сессии в tmux на Маке, timoserver и quiz видны с правильным статусом.
- Запрос разрешения или вопрос сессии → notch показывает его ≤3 с, одно уведомление.
- Ответ из notch доходит в нужную сессию; при чужом наборе или `running` — отказ.
- Нет ложного «ждёт меня», пока сессия работает.
- После сна Мака и обрыва Wi-Fi всё переподключается само.
- Капри в простое: <1% CPU, <150 МБ.

## 7. Риски и что проверить

- Тексты и типы `Notification` у Claude Code меняются между версиями — разбор
  терпимый к неизвестным типам, фолбэк на экран.
- Хуки срабатывают только в сессиях, запущенных после установки, — старые сессии
  видны через разбор экрана, пока их не перезапустят.
- На Маке `/opt/homebrew/bin/claude` падает на Node 25; рабочий — `~/.local/bin/claude`.
  Установщик и «Открыть» должны использовать рабочий бинарь.
- `notify` Codex занят Computer Use — только через обёртку.
- Вывод экрана может содержать секреты — резать перед отправкой в Codex.

## 8. Вне MVP

Бродящий персонаж и анимации, Telegram и Mini App, голос (Tima Transcriber),
память, управление сессиями, запущенными вне tmux, запуск новых сессий из Capri.
