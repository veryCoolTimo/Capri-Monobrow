# Capri — присутствие: музыка, «сидит на окнах», терминал, голос, модель персонажа (план 2026-11-01)

Следующий шаг после `2026-10-31-capri-character-scenes-plan.md`. Новое направление от Тимофея:
**у Capri нет постоянного места на экране и нет случайных окон.** Она появляется только в ответ на его
действия: открыл приложение — телепортировалась на край окна, посидела, съязвила; открыл терминал с
Claude — вылезла и смотрит/комментирует сессию; включил музыку — около минуты кивает, потом молнией
уходит обратно в «монобровь» (глаза в notch). Везде — красивые молнии и глитчи. Нужно больше анимаций и
«моментов», голосовой ввод через его локальную модель (Nemotron streaming, не Whisper) и начало
настоящей модели персонажа.

Этапы маленькие, каждый ставится и проверяется отдельно, в порядке ценности. Коммит и push — после
каждого этапа, только по решению Тимофея. Тайм-коды, номера кадров и id видео — только в
`work/research/notes/` (gitignored), в репозиторий не попадают.

## 0. Общие рамки (для всех этапов)

- **Нет фона по таймеру.** Фоновые сцены (`ambient`: телепорт в угол, окно, сессии, захват) —
  выключены по умолчанию и убраны из меню настроек в «Экспериментальное». Если на окне нет места —
  сцена пропускается, **в угол не падаем**.
- **Компьютером не управляем**, как раньше: `StagePanel` `[.borderless, .nonactivatingPanel]`,
  `canBecomeKey/Main = false`, без `NSApp.activate`, без `.fullScreenAuxiliary`. Основное окно Capri
  никогда не открывается само.
- **Без новых разрешений на этапах 1–3.** Окна — `CGWindowListCopyWindowInfo` без `kCGWindowName`;
  приложения — `NSWorkspace`; перетаскивание — глобальный монитор мыши (без разрешения). Микрофон
  (этап 4) — единственное новое разрешение, запрашивается только при первом нажатии push-to-talk.
- **CPU:** вне сцены ≈ 0 (панели нет, таймеров нет, мониторов мыши нет). Во время «сидения» —
  цель ≤ 3 % одного ядра: 24 fps только в прыжке, 12 fps в речи/кивании, иначе кадр только при
  изменении (моргание).
- Полноэкранный режим, звонок, игра, тихие часы, «спрятать на час» — Capri не появляется, идущая
  сцена уходит в notch.
- `needsInput` у любой сессии обрывает сцену (молния домой ≤ 0.3 с) — дальше обычный alert notch.
- Не трогаем `SessionReducer.swift`, `Codex.swift`-протокол и их тесты, кроме явно указанного.
- Перед установкой на Мак — контактные листы кадров (`scene sheet`), смотрю их сам.

### Почему не видно содержимое сессий votek, votek2, votek3

Они живут на хосте `quiz` (прод). `Settings.codexPrivateHosts` по умолчанию `["quiz"]`, поэтому
`Assistant.prompt` отправляет в Codex только имя и статус этих сессий, без текста экрана. Это
сознательная защита прода. Включается в Настройках: «Отправлять в Codex сессии с quiz». Мелкая
правка в этапе 1: когда содержимое скрыто, помощник говорит, **где** это включить, а не просто «скрыто
настройками».

## Этап 1. Музыка ≈ 60 с → телепорт в монобровь; молнии и глитчи на всех переходах — ✅ сделано 2026-11-01 (см. VALIDATION.md)

**Зачем первым:** уже есть `vibe`, `NowPlayingMonitor`, `MusicController` — меньше всего нового кода,
сразу видно новое поведение «пришла — ушла».

**Поведение.**
- Старт воспроизведения (первый после ≥ 10 мин тишины или по запросу «включи …») → молния из notch на
  окно Spotify/Музыки, если оно видно на экране notch; иначе на фронтальное окно (верхний край);
  места нет → только кивание в notch, без стола.
- ~60 с кивание под бит (`nod`, `onBeat`), ноты-глифы, 1–2 реплики-бабла («о, это я знаю», «громче»).
- На 58–60 с — «втягивание в монобровь»: распад на полосы + лента/молния к notch, вспышка в notch,
  короткий кивок notch (уже есть). Пауза/стоп плеера — домой сразу. Смена трека во время сцены — глитч 1,
  таймер не продлевается.
- Сцена `.vibe` больше не ходит в угол.

**Переходы везде (общая библиотека).** Все сцены входят и выходят через один набор эффектов:
`burstIn` (из вспышки сплошного цвета), `glitchBars` (проявление/распад полосами с RGB-сдвигом),
`columnSmear` (кадр «стекает» вертикальными столбцами), `ribbonOut` (уход лентой), `boltChain`
(циановая молния из коротких прямых сегментов, 2–4 кадра, ответвления). Выбор — детерминированно по
seed, чтобы два подряд выхода не были одинаковыми.

**Файлы.**
- CapriKit: `SceneTimeline.swift` (новая длительность `vibe` 60 с, фаза `home` = втягивание в notch),
  новый `Transitions.swift` (чистые функции: `TransitionKind`, `transition(kind, t, from:, to:) ->
  TransitionFrame` — полосы, сдвиг, столбцы, сегменты молнии с ответвлениями), `CharacterDirector.swift`
  (`ambient` по умолчанию выключен; `musicStarted` без фолбэка в угол).
- Capri: `CapriEffects.swift` (отрисовка `TransitionFrame`, палитра из библии: молния ≈ `#00E5F0`,
  маска `#00FC67`, волосы `#FB0D49`, фиолетовая кромка `#7A2CF4`), `CharacterCenter.swift`,
  `CharacterStage.swift`, `SettingsView.swift` («Фоновые сцены» → выкл., в «Экспериментальное»),
  `Assistant.swift` — только текст подсказки про скрытые хосты.

**Чистая логика + тесты.**
- `SceneTimelineTests`: фазы vibe; на 58–60 с — `recall` в notch; пауза → `home` за ≤ 0.6 с; потолок 60 с.
- `TransitionsTests`: при `t = 0` и `t = len` кадр равен началу/концу; сегменты молнии соединяют точки,
  длина сегмента в пределах; одинаковый seed — одинаковая молния; без повтора вида два раза подряд.
- `CharacterDirectorTests`: ambient выключен по умолчанию → `skip ambient-off`; музыка без окна →
  `notchVibe`, не угол.

**Разрешения:** нет.
**Риски:** окно Spotify часто свернуто/за другими окнами → чаще «только notch»; яркие вспышки —
уважать Reduce Motion (без вспышек сплошного цвета, только полосы).
**Решает Тимофей:** длительность (60 с или «пока трек») и нужны ли реплики во время музыки.

## Этап 2. «Сидит на окнах»: телепорт на открытое приложение + банк язвительных реплик — ✅ сделано 2026-11-01 (см. VALIDATION.md)

> **Отзыв Тимофея 2026-11-01 сильнее текста ниже:** «появляется и говорит фразы рандомно», «слишком часто на экран
> попадает». Поэтому: садится только когда он **запускает** приложение (не ⌘-Tab, не любая активация), только первый
> запуск этого приложения за день, без жребия; ≥ 10 мин между посадками, ≤ 2 в час, ≤ 8 в день, не в первые 2 мин
> после запуска Capri и не раньше 5 мин после другой сцены. Реплики — про то, что происходит (приложение по имени,
> сколько сессий ждут/работают, что играет, сколько дней не открывал, время суток), не случайные. Одна настройка
> «Садиться на окна запущенных приложений» (и пункт меню) выключает всё. Молнии — прежние розовые игольчатые.

**Поведение.**
- Сигналы: `NSWorkspace` didActivate / didLaunch / didTerminate + debounce 1.2 с (быстрый ⌘-Tab —
  ничего). Рамки окон — `CGWindowListCopyWindowInfo` (bounds, номер, z-order, без заголовков).
- **Когда садится:** первое открытие приложения за рабочую сессию (или ≥ 4 ч с прошлого раза), ~70 %.
  Лимиты: ≥ 3 мин между визитами, ≤ 6 в час, ≤ 25 в день.
- **Когда молчит:** тихие часы (предложение 00:30–09:00), fullscreen, звонок (камера/микрофон заняты
  чужим процессом + список приложений звонков), игры (`LSApplicationCategoryType`), системные UI,
  менеджеры паролей, сама Capri, пользовательский список «здесь не сидеть».
- **Усталость:** прогнал дважды подряд → час только терминал и музыка.
- **Где садится:** верх-право окна → верх-лево правее кнопок окна → свисает с правого края → нижний
  край. Точка отклоняется, если её перекрывает другое окно; кнопки закрыть/свернуть/развернуть
  никогда не закрываем.
- **Визит 7–14 с:** прилёт (переход из этапа 1) → бабл с печатью реплики → сидит (моргает, косится на
  курсор) → уход. Окно тащат — следует за ним; уход при смене приложения, fullscreen, перекрытии точки,
  `needsInput`. Клик по глазам — прогнать; клик по баблу — помощник с этой репликой.
- Панель после прилёта сжимается до ~300×140 (сейчас тянется от notch до цели).

**Реплики.** Локальный русский банк: 12 категорий приложений (браузер, мессенджер, почта, IDE,
дизайн, финансы, видео, заметки, файлы, настройки, музыка, прочее), реплики по времени суток, без
повтора последних 10, ≥ 6 на категорию. Тон из сериала: дерзкая, самоуверенная, быстро от «^^» к
хищной ухмылке. Опционально (выкл.): раз в день Codex пишет пачку реплик — отправляются только
категория, время и имя приложения; тот же валидатор; кэш в `~/.capri/`.

**Файлы.**
- CapriKit (новые): `AppCatalog.swift` (`AppCategory`, категория по bundle id и Info.plist, never-list,
  блок-лист), `QuietHours.swift`, `PerchPolicy.swift` (как `CharacterDirector`: события `activated`,
  `terminalSession`, `musicStarted` → `.perch(kind)` / `.skip(reason)`), `PerchLayout.swift`
  (`PerchSpot`, кандидаты, перекрытия, `place` после сдвига окна, прямоугольник панели),
  `PerchTracker.swift` (сэмплы окна и перетаскивание → `stay/hold/hop/leave`, `nextPoll`),
  `PerchTimeline.swift` (кадры, `nextChange`, прыжок между точками, бабл в `SceneFrame`),
  `PerchLines.swift` (банк, `valid`, `pick`, разбор реплик Codex), `CallGuard.swift`.
- Capri (новые): `PerchCenter.swift` (наблюдатели NSWorkspace, опрос окна 2 Гц, 10 Гц только при
  перетаскивании, глобальный монитор мыши только пока сидит), `AppWatcher.swift`.
- Capri (меняются): `CharacterStage.swift` (сжатая панель, бабл), `SettingsView.swift`
  («Садиться на окна», тихие часы, список «не сидеть здесь»), `AppDelegate.swift` (меню
  «Прогнать на час», debug `perch <bundle>`, `dump perch`), `NotchController.swift` (правый клик —
  «Спрятать на час» уже есть).

**Тесты (`PerchTests.swift`).** PerchPolicy — по тесту на каждую причину skip, seen/revisit/terminated,
лимиты, усталость, тот же seed → те же решения; QuietHours через полночь; AppCatalog; PerchLayout —
порядок точек, кнопки окна не перекрыты, `place` следует за окном, панель в пределах экрана;
PerchTracker — каждое действие и частота опроса; PerchTimeline — фазы, `nextChange`; PerchLines —
все реплики валидны, ≥ 6 на категорию, нет повторов, разбор ответа Codex; CallGuard.

**Разрешения:** нет (проверить на Маке, что CoreMediaIO/CoreAudio «устройство занято» не спрашивают
доступ — до этого CallGuard работает только по списку приложений).
**Риски:** раздражает → консервативные лимиты и усталость с первого дня; окна без рамок/нестандартные
(Electron, полупрозрачные) — неверные bounds; несколько мониторов; CPU при перетаскивании.
**Решает Тимофей:** только экран notch или все экраны; тихие часы; вероятность/лимиты; реплики от Codex.

## Этап 3. Терминал с Claude: вылезает и смотрит на сессию — ✅ сделано 2026-11-01 (см. VALIDATION.md)

> **С отзывом Тимофея:** повод — только свежее открытие терминала/подключение/запуск агента (≤ 3 мин), не ⌘-Tab; лимиты
> общие с посадками (≥ 10 мин, ≤ 2/час); выключается той же настройкой. Termius (свой ssh) не поддерживается.

**Поведение.**
- Терминал стал фронтальным (Terminal, iTerm2, Ghostty, WezTerm, Alacritty) → «обратный
  `TerminalLocator`»: какие tmux-сессии и ssh-хосты живут под этим окном (дерево процессов).
- Если там есть сессия Claude/Codex, которую видит Capri, — «влезает в экран»: окно терминала
  краснеет и стекает столбцами (`columnSmear` по рамке окна, только рисунок поверх, ~0.6 с), из угла
  вылезает мини-маска и садится на угол окна.
- Смотрит до 60 с, пока сессия работает: зрачки следят за курсором/низом окна, реплики на смену
  статуса («опять тесты», «о, закончил», «ждёт тебя»). Для неприватных хостов — реплики по ключевым
  словам из хвоста экрана (error, failed, passed, commit…); для приватных (`quiz`) — только статус.
- Сессия ушла в `idle` пока она сидит — злорадная ухмылка + дрожь, уход в notch. `needsInput` — сразу
  в notch, дальше обычный alert.
- Кулдаун на одно окно терминала — 15 мин.

**Файлы.**
- CapriKit: `TerminalLocator.swift` (+ `targets(underTerminal:)`), новый `SessionRemark.swift`
  (реплики из перехода статусов и хвоста экрана; `nil`-хвост для приватных хостов), `PerchPolicy`
  (`terminalSession`, кулдаун), `Transitions.swift` (`columnSmear` по произвольному прямоугольнику).
- Capri: `PerchCenter.swift` (подписка на `store.$sessions` только пока сидит на терминале),
  `ProcessTable.swift` (если нужно больше полей), `CharacterStage.swift`.

**Тесты.** `TerminalLocatorTests` — фиксированные деревья процессов (tmux attach, ssh -t … tmux,
вложенный shell) → верные хосты/сессии; `SessionRemarkTests` — переходы статусов, ключевые слова,
приватный хост без текста, нет повторов; `PerchPolicy` — кулдаун терминала, `needsInput` обрывает.

**Разрешения:** нет (дерево процессов — уже используется для ответа в терминал).
**Риски:** несколько вкладок/сплитов в одном окне — не знаем, какая видна (без Accessibility) → берём
только если под окном ровно одна сессия Capri, иначе реплики только по статусу «одной из»; хвост
экрана может содержать чувствительное — не логировать, не отправлять в Codex для приватных хостов.
**Решает Тимофей:** включать ли реплики по тексту экрана для неприватных хостов по умолчанию.

## Этап 4. Голос: push-to-talk через Nemotron streaming + команды — ✅ сделано 2026-11-01 (см. VALIDATION.md)

> **Как сделано (по «Решениям Тимофея»):** ⌃⌥Space коротко — помощник, как раньше; держать ≥ 0,28 с — голос. Голос
> только в notch, на рабочий стол Capri из-за него не выходит (и «включи …» голосом — без окна музыки на столе).
> «Запиши» → Apple Заметки, «напомни» → Apple Напоминания (AppleScript; своё хранилище `Reminders.swift` /
> `ReminderCenter` и `RemindersTests` не понадобились — сроки ведут Напоминания). Модель — из кэша HF, скачивание
> (~750 МБ) — только кнопкой в Настройках → Голос. Прогрев — при первом раскрытии notch после запуска и при нажатии.
> Хелпер — `capri-asr` в `Contents/MacOS`, `CTranscribe.framework` — в `Contents/Frameworks`.

**Движок.** transcribe.cpp (MIT, ggml + Metal) с моделью nemotron-3.5-asr-streaming-0.6b (gguf
Q8_0, лицензия OpenMDW-1.1). Русский и английский, автоопределение языка, пунктуация, частичный
текст. Handy как бэкенд не годится (нет API, только вставка текста). На M4 Pro: подача 100 мс аудио
≈ 3 мс, финализация после отпускания ≈ 15 мс, первый текст ≈ 0.5 с после начала речи; ~340 МБ памяти.

**Архитектура.**
- **Отдельный хелпер `capri-asr`** (SwiftPM в `tools/capri-asr`, Swift-биндинг transcribe.cpp на
  закреплённом коммите): stdin — PCM 16 кГц mono Float32 + управляющие строки `begin/end/cancel`;
  stdout — JSON-строки `{"partial":…}` / `{"final":…}`. Модель грузится один раз, выход после 5 мин
  простоя (память возвращается). Отдельный процесс: `Package.swift` Capri не трогаем, падение не
  роняет Capri, нет падения ggml-metal на выходе по ⌘Q.
- **Сборка:** `scripts/build-asr-macos.sh` (клон на коммите, xcframework только macOS, `swift build
  -c release`); `scripts/build-macos.sh` кладёт `capri-asr` в `Contents/MacOS` и `CTranscribe.framework`
  рядом, ad-hoc `codesign --deep`, `THIRD-PARTY-LICENSES.md` в бандл.
- **Модель не в бандле:** берётся из кэша Hugging Face на Маке, иначе скачивается из того же репо;
  иначе в notch понятное «модели нет».
- **Микрофон в Capri:** `NSMicrophoneUsageDescription` в Info.plist (`build-macos.sh`). Нажатие →
  `AVAudioEngine`, tap `inputNode`, `AVAudioConverter` → 16 кГц mono, **~500 мс тишины в начале**
  (иначе теряется первое слово «Капри»), поток в хелпер. Отпускание → `end`, движок стоп (оранжевая
  точка только пока говорит). Частичный текст — в notch, глаза «слушают»; финальный — в роутер команд.
- **Клавиша:** удержание ⌃⌥Space — в `HotKey.swift` добавить `kEventHotKeyReleased` (Carbon, без
  разрешений). Удержание правого Option — отдельный опциональный режим, просит Input Monitoring.
- Прогрев хелпера при первом открытии notch после логина (первая загрузка 2.5–6 с).

**Команды (чистый роутер `VoiceIntent`).**
| Фраза | Действие |
|---|---|
| «включи …», «пауза», «дальше» | `MusicCommand.parse` (уже есть) → `MusicController` |
| «запиши/заметка …» | заметка в `~/.capri/notes.md` (или Apple Notes — решает Тимофей) |
| «напомни через 20 минут / в 18:00 …» | локальное напоминание: `UNUserNotification` + сцена-бабл в срок |
| «найди/посмотри в интернете …» | Codex с `web_search` включённым только для этого запроса, ответ — сцена `answer` со ссылками; открыть ссылку в браузере — только по клику |
| «ответь votek2 …» / «что с сессиями» | существующий помощник/`Reply` (с подтверждением перед отправкой в сессию) |
| всё остальное | помощник (как ввод с клавиатуры) |

**Файлы.**
- Новые: `tools/capri-asr/` (Package.swift, main.swift), `scripts/build-asr-macos.sh`,
  CapriKit `VoiceIntent.swift` (разбор фразы → intent, относительное/абсолютное время напоминаний),

## Этап 5. Модель персонажа (2D векторный риг) + новые моменты — ✅ сделано 2026-11-01 (мини-маска, руки, волосы, моменты; позы тела — позже; см. VALIDATION.md)

**Почему векторный риг.** Дизайн Capri — плоские полигоны без контуров: маска `#00FC67`, чёрные
шипы, миндалевидные глаза с синим зрачком, белый вырез-рот, огромная масса малиновых осколков-волос
с искрами и фиолетовой RGB-кромкой. Это переводится в вектор без потерь. Мини-маска из сериала (одна
пластина, у которой вырастают руки) — готовая форма «сидит рядом с вещами». Эмоции — смена 3–4 слоёв
(веки, зрачки, рот). Масштаб от notch до полного экрана, прозрачный фон — по-настоящему сидит на чужом
окне. Клипы сериала остаются только для телепортов и больших всплесков эмоций (злость, перегрузка).
Спрайт-листы руками или FLUX — нет: слишком много кадров и не держат единый дизайн; FLUX — только
черновики поз тела для перерисовки.

**Шаги (каждый — отдельный маленький релиз).**
1. **Риг мини-маски** — пластина (анфас, ¾, значок), 5 состояний глаз (открыт, полувеко, щёлки, `><`,
   `^^`), зрачок с бликом и кольцом, 4 рта (клык, зигзаг-бормотание, большой осколок-челюсть, акулья
   ухмылка), шипы. Формат — собственный JSON слоёв (`CapriRig`: полигоны, точки привязки, якоря),
   отрисовка в SwiftUI `Canvas`. Рисую по контактным листам из локальной библии; структуру слоёв
   смотрю у MIT-проекта capri-companion (только как референс). Мини-маска заменяет клипы в «сидит на
   окне» и в терминале.
2. **Руки** — два сегментированных плеча с кистями: помахать, напрячь бицепс, «кепка», показать пальцем
   на строку терминала.
3. **Волосы** — 12–20 отдельных осколков, процедурное покачивание, шейдер искр (меняются каждый кадр
   на 12 fps), фиолетовая RGB-кромка.
4. **Позы тела (позже)** — стоит у рамки окна, сидит на крае, растеклась лужей, висит на крае.

**Новые моменты (на риге + процедурно).**
| Момент | Где | Как |
|---|---|---|
| Машет «^^» при прилёте | окна | риг: руки + `^^` |
| Косится на курсор, скука, зевок | окна | риг: полувеко, рот-зигзаг |
| Засыпает (никто не трогает 40+ с) | окна | риг: веки медленно вниз, «z» |
| Язвительный смех `><` | реплики | риг: челюсть-осколок + тряска |
| Смотрит в терминал | этап 3 | зрачки за новыми строками |
| Злорадство над сессией | этап 3 | акулья ухмылка + дрожь |
| Удивление | смена трека, ошибка | риг: широкие глаза + вспышка |
| Злость (красный глаз-мишень) | ошибка сессии | клип |
| Перегрузка (рой глаз) | много `needsInput` сразу | клип |
| «Хакает» | Codex ищет в интернете | процедурная циановая молния |
| Тихий idle — неоновый контур | долгая сцена | векторная линия |
| Растекается по краю окна | уход | спрайт-силуэт + процедурная волна |
| «Связь потеряна» — пиксельный призрак | хост оффлайн | процедурный эффект |

| Танец под бит | музыка | риг синхронно с `onBeat` |

**Файлы.** CapriKit: `CapriRig.swift` (модель слоёв, состояния лица, интерполяция поз — чистое),

**Разрешения:** нет.
**Риски:** самое трудоёмкое и субъективное — сначала только мини-маска, показать лист Тимофею до
